# Pepa — видение продукта

Pepa — локальная платформа автоматизаций для Windows. Рабочее название, взято из имени репозитория.

## Зачем

Пользователь собирает автоматизации любой сложности — от «каждое утро переложить файлы» до долгих процессов
с ожиданием ответов, ветвлениями, несколькими приложениями и браузерными профилями — и уверен, что платформа
не сделает ничего лишнего, не повторит уже выполненное и честно скажет, где остановилась и почему.

Это не рекордер мыши. Запись действий — лишь один из способов получить сценарий.

## Для кого

- Человек без навыков программирования: собирает сценарий из блоков, видит понятные подсказки и ошибки.
- Опытный пользователь: выражения, переменные, циклы, обработка ошибок, повторы, параллельные процессы.

## Три способа создать сценарий — один формат, один движок

| Способ | Что делает пользователь | Результат |
|---|---|---|
| A. Конструктор | соединяет блоки на схеме | сценарий (граф) |
| B. Запись действий | показывает последовательность | тот же формат, устойчивые селекторы вместо координат, где возможно |
| C. Описание словами | ИИ предлагает сценарий | тот же формат, проходит ту же проверку, редактируется до запуска |

Никаких параллельных «систем автоматизации»: всё, что создано любым способом, исполняет один движок.

## Принципы

1. **Сначала надёжность.** Не выполнять незапланированного. Не продолжать при неожиданном поведении.
   Не повторять действие, если неизвестно, выполнилось ли оно. Не скрывать ошибок. Ошибка одного процесса не трогает другие.
2. **ИИ необязателен.** Движок, переменные, условия, ожидания, расписания и интеграции работают без ИИ.
   ИИ — подключаемый помощник для создания и объяснения сценариев; его отказ не ломает готовые автоматизации.
3. **Любая сложность, понятная настройка.** Простое — просто, сложное — возможно. Интерфейс скрывает лишнее, но не запрещает.
4. **Честность.** Неготовые функции явно помечены как неготовые. Платформа не обещает того, что не может проверить:
   однократность внешних действий, обход защит сайтов, «уникальность отпечатка» и т.п.
5. **Ручное возобновление после сбоя.** После перезапуска ничего не продолжается само; пользователь выбирает, что возобновить.

## Чем продукт не является

- Не антидетект-браузер (работаем с существующим AdsPower через его API).
- Не средство обхода ограничений сервисов: такое поведение не добавляется скрыто.
- Не облачный сервис: всё хранится и исполняется локально. (Архитектура позволяет позже запускать то же
  приложение на Windows-сервере, чтобы автоматизации работали без включённого домашнего ПК.)

## Критерий успеха

У пользователя постепенно появляется реально работающая платформа, которую можно развивать годами без переписывания ядра.
