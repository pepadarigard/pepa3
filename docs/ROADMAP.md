# План развития

Этап считается готовым только когда его поведение покрыто тестами и проверено запуском, а не когда код компилируется.

## Этап 0. Окружение и решения — ✅
- Аудит окружения, документы `docs/*`.

## Этап 1. Работающий фундамент — ✅ (первая версия; окно Windows проверено сборкой в CI, вручную — у пользователя)
- Модель сценария (граф), проверка с понятными сообщениями, выражения и шаблоны.
- Движок с сохраняемыми состояниями шагов, ожиданием-таймером, повторами, обработкой ошибок, паузой/остановкой,
  восстановлением после перезапуска без автозапуска, сверкой неизвестных результатов.
- Независимые экземпляры процессов, параллельное исполнение разных процессов.
- SQLite: сценарии, процессы, маркеры, шаги, журнал, настройки.
- Файловые действия в рабочей папке с проверкой результата.
- Локальный API + интерфейс: Главная, Сценарии, Конструктор (базовый), Выполнение, История, Интеграции, Настройки.
- Оболочка WPF + WebView2; сервер без окна для разработки.
- Тесты ядра, движка, адаптера и API; сборка и тесты на Windows в CI.

**Готово, когда:** пример-сценарии запускаются из интерфейса; процесс с ожиданием переживает перезапуск и
возобновляется вручную; сбой между действием и записью результата не приводит к повтору подтверждённого действия.

## Этап 2. События, очереди, ресурсы — ✅
- Система событий: входящие события с источником, дедупликацией по «ключу от повторов», явными состояниями
  обработки (принято → назначено → обработано; никому не подошло; нужно решение; пропущено).
- Блоки «Ждать событие» (выходы «Пришло» / «Тайм-аут») и «Отправить событие»; правила сопоставления: источник, вид,
  ключ, дополнительное условие, приоритет, окно «пришедшие раньше». Равные кандидаты — конфликт на решение
  пользователя, без совпадений — ничего не запускается. Событие для приостановленного процесса применяется только
  после ручного возобновления.
- Менеджер ресурсов: блоки «Занять ресурс» / «Освободить ресурс», очередь по порядку, тайм-аут ожидания,
  обнаружение взаимной блокировки, освобождение при завершении процесса и после сбоя, ручное освобождение.
- Запуск по расписанию (каждые N минут, по дням недели, один раз) и по событию; пропущенные во время закрытия
  запуски учитываются и показываются, но выполняются только по решению пользователя.
- «Вызвать сценарий» (с ожиданием итога) и «Запустить сценарий» (без ожидания), «Для каждого элемента».
- Интерфейс: события, конфликты и ресурсы на странице «Выполнение», автозапуск у сценария и в конструкторе,
  уведомления на главной, связи процесса (родитель, вызванные, ожидания, ресурсы).

**Готово, когда:** тесты на поступление нескольких событий, неоднозначное сопоставление, дедупликацию,
конфликт ресурсов и сохранность очередей после перезапуска зелёные. — Выполнено (см. `TESTING.md`).

## Этап 3. Развитие конструктора ✅
- ✅ Автоматическая раскладка, поиск по схеме (Ctrl+F), копирование и вставка блоков со связями (Ctrl+C/Ctrl+V,
  в том числе в другой сценарий — нужные переменные добавляются), копия выбранного (Ctrl+D), выбрать всё (Ctrl+A).
- ✅ Параллельные ветви: «Параллельно» (2–4 ветви) и «Дождаться всех ветвей» со структурной проверкой (ветви сходятся
  в одном слиянии, в середину ветви нельзя войти снаружи, ветви не сливаются раньше времени); ожидания ветвей идут
  одновременно, переживают перезапуск; «Завершение» в одной ветви заканчивает процесс и снимает ожидания других.
  Пример 11.
- ✅ Группы на схеме: рамка с названием, перетаскивание целиком, свернуть в один блок (связи и ошибки видны),
  на странице процесса — рамками. Подпроцесс — «Вызвать сценарий» (вынести часть схемы — копированием блоков).
- ✅ Отладка: «Пауза перед блоком» (точка останова) и запуск «Пошагово»; «Продолжить» выполняет блок,
  «Продолжить без остановок» — процесс до конца. Переменные видны на странице процесса.
- ✅ Шаблоны: «Сценарии» → «Из шаблона» — свой сценарий как копия любого примера.

## Этап 4. Windows и браузер ✅ (окна Windows — проверить на настоящих программах)
- ✅ Браузер через Playwright: Edge/Chrome, профиль Pepa с сохранением входа, переход, нажатие, ввод, клавиши,
  выбор в списке, флажки, прикрепление файла, вкладки, ожидание элемента и адреса, чтение, JavaScript, снимок,
  закрытие; проверка результата после сбоя.
- ✅ «Найти в тексте»: код из цифр, число, ссылка, почта, текст между словами, шаблон — например, код из сообщения
  Telegram для ввода на сайте.
- ✅ AdsPower: открытие профиля через Local API, подключение по CDP, профиль как ресурс, переподключение после
  перезапуска, настройки и проверка связи, выбор профиля в конструкторе.
- ✅ Telegram (пользовательский аккаунт, MTProto): вход в «Интеграциях», «Отправить сообщение» с проверкой по
  истории чата, «Ждать сообщение» из чата или любого чата с фильтром по тексту, сообщения за время простоя;
  кнопки ботов (под сообщением и на клавиатуре), отправка файла с подписью, сохранение вложений в рабочую папку;
  прокси SOCKS5 и MTProxy (ссылкой или полями, с проверкой).
- ✅ Окна Windows (UI Automation, FlaUI): запуск программы, поиск окна, нажатие, ввод, чтение, ожидание элемента,
  закрытие; клавиатура (сочетания, печать Unicode) и мышь в точке окна как запасной способ; мышь и клавиатура —
  общий ресурс. Проверено на имитации Windows; с настоящими программами — у пользователя.
- Дальше: просмотр элементов окна в конструкторе.

План этапа:
- Браузер через Playwright (обычный браузер пользователя — в пределах поддерживаемых способов подключения).
- AdsPower через Local API (сначала проверить документацию и доступность на бесплатном тарифе пользователя),
  подключение Playwright к запущенному профилю; профиль — ресурс с монопольным доступом.
- Windows UI Automation: поиск элементов, клики, ввод; запасной вариант — мышь/клавиатура (ресурс «ввод»)
  с честной пометкой о меньшей надёжности.
- Telegram: MTProto для пользовательского аккаунта и/или Bot API для бота; Telegram Desktop — через UI Automation
  или ввод, если API не подходит.

## Этап 5. Запись действий и ИИ — частично ✅
- ✅ Запись в браузере (браузер Pepa или профиль AdsPower): нажатия, ввод, выбор, флажки, Enter/Escape, введённые
  вручную адреса и новые вкладки → блоки с устойчивыми селекторами; пароли не записываются (переменная).
- Запись в окнах Windows (элементы UI Automation), координаты — только как запасной вариант.
- ✅ ИИ-помощник в конструкторе (необязательный, свой ключ API Anthropic): описание словами → черновик блоков с
  переменными и связями; черновик проходит ту же проверку, ошибки отправляются модели на исправление (до 2 раз),
  оставшиеся показываются; вставка — как скопированных блоков, в новый сценарий — вместо заготовки «Начало → Конец».
  Проверено на имитации Claude API (настоящий SDK); с настоящим ключом — проверить у себя.
- Помощник: объяснение и правка существующего сценария (пока — только составление новых блоков).
