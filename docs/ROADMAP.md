# План развития

Этап считается готовым только когда его поведение покрыто тестами и проверено запуском, а не когда код компилируется.

## Этап 0. Окружение и решения — ✅
- Аудит окружения, документы `docs/*`.

## Этап 1. Работающий фундамент — ✅ (первая версия)
- Модель сценария (граф), проверка с понятными сообщениями, выражения и шаблоны.
- Движок с сохраняемыми состояниями шагов, ожиданием-таймером, повторами, обработкой ошибок, паузой/остановкой,
  восстановлением после перезапуска без автозапуска, сверкой неизвестных результатов.
- Независимые экземпляры процессов, параллельное исполнение разных процессов.
- SQLite: сценарии, процессы, маркеры, шаги, журнал, настройки.
- Файловые действия в рабочей папке с проверкой результата.
- Локальный API + интерфейс: Главная, Сценарии, Конструктор (базовый), Выполнение, История, Интеграции, Настройки.
- Оболочка WPF + WebView2; сервер без окна для разработки.
- Тесты ядра, движка, адаптера и API; сборка и тесты на Windows в CI.

**Готово, когда:** пример-сценарии запускаются из интерфейса; процесс с ожиданием переживает перезапуск и
возобновляется вручную; сбой между действием и записью результата не приводит к повтору подтверждённого действия.

## Этап 2. События, очереди, ресурсы
- Система событий: входящие события с источником, дедупликацией по идентификаторам, явными состояниями обработки.
- Блок «Ждать событие» с тайм-аутом (порты «событие» / «тайм-аут»), правила сопоставления события с процессом;
  неоднозначные совпадения — в конфликт на решение пользователя, без совпадений — ничего не запускается.
- Менеджер ресурсов: резервирование (профиль браузера, окно, мышь/клавиатура), очередь ожидающих ресурс,
  сверка блокировок после сбоя.
- Расписания (cron-подобные) и запуск по событию; пропущенные во время закрытия запуски — только после ручного подтверждения.
- Подпроцессы (вызов сценария из сценария), «для каждого элемента».

**Готово, когда:** тесты на поступление нескольких событий, неоднозначное сопоставление, дедупликацию,
конфликт ресурсов и сохранность очередей после перезапуска зелёные.

## Этап 3. Развитие конструктора
- Параллельные ветви (разделение/слияние со структурной проверкой), группы, подпроцессы на схеме.
- Отладка: пошаговый запуск, точки останова, просмотр переменных на каждом шаге.
- Автоматическая раскладка, поиск по схеме, копирование/вставка блоков, шаблоны.

## Этап 4. Windows и браузер
- Браузер через Playwright (обычный браузер пользователя — в пределах поддерживаемых способов подключения).
- AdsPower через Local API (сначала проверить документацию и доступность на бесплатном тарифе пользователя),
  подключение Playwright к запущенному профилю; профиль — ресурс с монопольным доступом.
- Windows UI Automation: поиск элементов, клики, ввод; запасной вариант — мышь/клавиатура (ресурс «ввод»)
  с честной пометкой о меньшей надёжности.
- Telegram: MTProto для пользовательского аккаунта и/или Bot API для бота; Telegram Desktop — через UI Automation
  или ввод, если API не подходит.

## Этап 5. Запись действий и ИИ
- Запись: браузер (селекторы), Windows (элементы UI Automation), координаты — только как запасной вариант.
- ИИ-помощник: описание → сценарий, объяснение и правка сценария; результат проходит ту же проверку.

## Этап 6. Расширения
- Пользовательские блоки и интеграции через контракты `INodeExecutor` + описание блока.
- Новые интеграции по реальным потребностям.
