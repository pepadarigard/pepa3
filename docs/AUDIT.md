# Аудит проекта (ноябрь 2026)

Что проверяли, что нашли, что исправлено и что осталось. Решения по исправлениям — D-090 в `docs/DECISIONS.md`
(и уточнение D-021). Новые находки дописывайте сюда же: раздел «Не исправлено» — список открытых работ.

## Как проводился

- Пять независимых проверок по областям: безопасность; движок и хранилище; адаптеры (файлы, таблицы, HTTP, почта,
  браузер и AdsPower, Telegram, окна Windows, ИИ-помощник); локальный API и интерфейс; тесты и сопровождаемость.
- Каждую серьёзную находку отдельно пытался опровергнуть другой проверяющий: читал код и воспроизводил сценарий (тесты
  на копии репозитория, настоящий браузер, SQLite). В отчёт как «подтверждённые» попали только те, что опровергнуть не
  удалось. Находки низкой важности перекрёстно не проверялись — их проверили при исправлении.
- Параллельно четыре агента составили карты подсистем — по ним переписаны `docs/ARCHITECTURE.md` и написан `AGENTS.md`.
- Каждое исправление — с тестом, который падает на прежнем коде (проверено откатом исправления).

## Общая оценка по областям

- **Безопасность.** Локальный API защищён хорошо: только 127.0.0.1, случайный токен в заголовке, проверка Host
  (против DNS rebinding); попытки обойти путь (`//api`, `/api;`, `/%61pi`) не проходят. Маскирование секретов и
  DPAPI-шифрование ключей продуманы и покрыты тестами, песочница рабочей папки строгая. Слабые места были на краях:
  запись в браузере, черновики ИИ-помощника, ключ AdsPower, проверка «своей страницы» в окне.
- **Движок и хранилище.** Запись через единственного писателя (WAL, `synchronous=FULL`), миграции с копией перед ними,
  уникальные ключи происхождения против двойных запусков, осторожное восстановление. Не хватало защиты от «разгона»:
  самозапускающийся автозапуск, повтор первого элемента цикла, квадратичный рост хранилища у циклов.
- **Адаптеры.** Модель итогов соблюдается последовательно: ошибки ввода — отказ, неясный итог — «неизвестно», «сделано или
  нет» проверяется во внешнем мире. Слабые места — где правило из одного места не применено в другом (пустая подстановка
  в ожиданиях почты и Telegram, маска списка файлов).
- **API и интерфейс.** Контракт аккуратный, кнопки — только из `allowedActions`, рискованные решения подтверждаются.
  Слабое место — поток обновлений при пакетах запусков и неполная защита от повторной отправки.
- **Тесты и сопровождаемость.** Сильная сторона: настоящий SQLite, управляемое время, внедрение сбоев, настоящий браузер.
  Слабые места: сборка могла выглядеть зелёной при ошибках, код ввода в окна Windows не тестировался, очень крупные
  классы, документация отставала от кода.

## Опровергнутые находки

- **Блоки браузера выходят из рабочей папки через `file://`.** Механизм есть (адрес передаётся браузеру как есть), но
  такой адрес пишет в сценарий сам пользователь — это чтение своего файла своим браузером. Ссылки из чужих писем и
  сообщений до блока не доходят: `payload.links` у писем и «Найти в тексте» → «Ссылку» дают только http(s), кнопки-ссылки
  Telegram Pepa не открывает.
- **Расширения и `pepa.db` доверяются папке данных, в которую могут писать другие пользователи.** В такой раскладке
  (переносная копия на диске с правами «изменять» для всех) рядом лежат и сам `Pepa.exe` с библиотеками — заменить можно
  их; проверка папки расширений эту дыру не закрывает. Где распаковать Pepa, решает пользователь.
- **55 тестов браузера пропускаются молча, и CI остаётся зелёным.** В CI браузер есть в обоих заданиях (последний
  запуск: 72 прошли, 0 пропущено). Тем не менее CI теперь требует браузер явно (№ 12) — на случай смены образа.

## Не исправлено (открытые работы)

Найдено, но не исправлено — по важности. Перед работой сверьтесь с кодом.

1. **Смена часового пояса во время работы** не учитывается: уже рассчитанный следующий запуск расписания не
   пересчитывается до запуска. (Перевод часов в интервалах «каждые N часов» исправлен — см. ниже.)
2. **Пределы выражений Jint соблюдаются не полностью:** тайм-аут регулярного выражения — 10 с (а не 2 с, как у всего
   выражения), память проверяется только между инструкциями; часть вычислений идёт под общими замками маршрутизации и
   записи — тяжёлое выражение в условии события задерживает остальные процессы.
3. **Хранилище под нагрузкой (дополнительно к № 3):** страница процесса загружает все шаги без постраничности; срок
   хранения удаляет пачками по 500 процессов независимо от размера (долго держит замок записи). (Ограничение размера WAL —
   `journal_size_limit` 64 МБ — и проверка свободного места перед резервной копией добавлены.)
4. **Запись в браузере — вне модели ресурсов** (запись в окнах Windows держит `desktop:input`, запись в браузере —
   профиль не занимает): процесс может открыть тот же профиль во время записи.
5. **Секреты, записанные в настройках блоков буквально** (а не переменной), уходят ИИ-помощнику при «Объяснить»/«Изменить»
   вместе со сценарием. Запись в браузере секретных значений больше не записывает; можно дополнительно скрывать такие
   значения в `ScenarioPrompt.ToDraft`.
6. **Почта:** обещание D-069 «сломанное письмо не блокирует ящик» проверено только для того вида ошибки, который
   имитируют тесты.
7. **Интерфейс:** строки процессов и элементы «Сейчас работают»/«Быстрый запуск» открываются только мышью (нет ссылок и
   фокуса с клавиатуры); подтверждение опасного действия ставит фокус на опасную кнопку; ошибки проверки в конструкторе
   иногда молча игнорируются; `ui/src/api/types.ts` — ручная копия `Dtos.cs` без проверки контракта (уже разошлась:
   нет `WaitKind` `join` и назначения `question`); `request()` не передаёт сигнал отмены в `fetch`.
8. **Сопровождаемость:** `ApiEndpoints.MapPepaApi` — один метод ~860 строк, `ProcessEngine` — ~6,3 тыс. строк в 8 файлах,
   `TelegramService` — ~2,2 тыс., `BrowserSessions` — ~1,7 тыс. Разделять постепенно, по областям, с тестами.
9. **Сборка:** артефакт `Pepa-win-x64` публикуется из любой ветки (скачивать — из основной); журналы `logs/` не
   ротируются.
10. **Проверка на реальном ПК** — по-прежнему не выполнена: AdsPower, Telegram, окна Windows, трей, сон и пробуждение
    проверены на имитациях (`docs/CHECKLIST.md`).
