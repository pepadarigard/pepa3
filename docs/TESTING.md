# Тестирование

Надёжность проверяется автоматическими тестами поведения, а не ручным запуском. Внешние сервисы заменяются
имитациями там, где это позволяет проверить логику без реальных действий.

## Уровни

| Уровень | Где | Что проверяет |
|---|---|---|
| Ядро | `tests/Pepa.Core.Tests` | проверка сценариев, выражения и их песочница, шаблоны, сериализация |
| Движок | `tests/Pepa.Engine.Tests` | исполнение, ожидания, ошибки, повторы, параллельность, восстановление — на **настоящем SQLite** и **управляемом времени** (`FakeTimeProvider`) |
| Файлы | `tests/Pepa.Adapters.FileSystem.Tests` | рабочая папка, каждое действие и его проверка результата, сквозные сценарии с движком |
| API | `tests/Pepa.Host.Tests` | настоящий экземпляр на случайном порту: доступ, сценарии, запуск, настройки, блокировка экземпляра, поток событий, перезапуск |
| ИИ-помощник | `tests/Pepa.Assistant.Tests` | настоящий SDK Anthropic против имитации сервера (`FakeAnthropic`): формат запроса (схема ответа, кеш указаний, запасная модель), разбор и проверка черновика, исправление по ошибкам, правка без сброса настроек и неназванных полей, отказ при повторяющихся id, отказ и ошибки сервиса |
| Параллельные ветви | `tests/Pepa.Engine.Tests/ParallelTests.cs`, `PlatformApiTests.Parallel_sample_*` | одновременные ожидания, слияние один раз, перезапуск, ошибка и повтор в одной ветви, завершение в ветви (с остановкой вызванного сценария), вложенные участки, очередь ресурса по ветвям, поочерёдное выполнение ветвей, общий обработчик ошибок, запрет одного окна браузера в разных ветвях, структурная проверка |
| Интерфейс (модули) | `ui/src/**/*.test.ts` (vitest) | преобразование сценария ↔ схема, раскладка, помощники блоков, группы (хранение, рамка, свёрнутый вид со связями) |
| Интерфейс (сквозная) | `ui/e2e/smoke.cjs` (Playwright) | живой сервер + Chromium (и имитация Claude API для помощника): запуск с вводом, ИИ-помощник (ключ, черновик, вставка, объяснение, правка с показом изменений и отменой), прокси Telegram (проверка, сохранение без показа пароля), группа блоков (свернуть, сохранить, развернуть, перетащить, разгруппировать), конструктор (добавить блок, связать, сохранить, отменить/вернуть, запустить), пауза/продолжение/остановка, занятие ресурса и ожидание события с отправкой события из интерфейса, автозапуск по расписанию, история, тёмная тема |

### Инструменты имитации

- `ExternalWorld` + `TestActionNode` — внешнее действие с управляемым поведением: успех, подтверждённая ошибка,
  исключение до/после эффекта, остановка внутри действия до команды теста, принудительный итог проверки.
  Считает и вызовы, и фактические эффекты — отдельно.
- `FaultInjectingStore` — обёртка хранилища, которая «роняет» запись в заданный момент (например, при записи
  «подтверждено» для конкретного шага), а затем — все последующие записи (жёсткий сбой).
- `EngineHarness` — движок над временной базой; «перезапуск» и «аварийный перезапуск» создают новый движок над
  тем же файлом.

Браузер и AdsPower (`Pepa.Adapters.Browser.Tests`) проверяются на настоящем Chromium и маленьком тестовом сайте:
открыть, ввести, нажать с проверкой, прочитать, снимок, закрыть; отсутствующий и неоднозначный элемент не
нажимается; потерянный после перезапуска браузер сообщается. AdsPower — на имитации Local API, которая, как
настоящий AdsPower, запускает браузер с портом отладки: открытие и закрытие профиля, ключ API, запасной v1,
пауза между запросами, второй процесс ждёт профиль, переподключение после перезапуска без повторного открытия,
закрытый пользователем профиль. Браузер для тестов: `PEPA_TEST_BROWSER_PATH` или `PEPA_TEST_BROWSER_CHANNEL`
(в CI — Edge на Windows и Chrome на Linux); без браузера эти тесты пропускаются.

Telegram (`Pepa.Adapters.Telegram.Tests`) — блоки на имитации Telegram и настоящем движке: ответ только из своего
чата, фильтр по тексту, повтор сообщения обрабатывается один раз, потерянное подтверждение отправки проверяется по
истории чата (второй раз не отправляется), сообщение за время простоя доходит до ждущего процесса без автозапуска.
Проверка отправки не принимает за своё такое же сообщение, отправленное раньше, и находит своё при обрезанных
пробелах; подтверждённая проверкой отправка заполняет переменную; отказ Telegram — ошибка, а не «итог неизвестен».
Ответ, пришедший вовремя, пока Pepa была закрыта, принимается после «Продолжить», а тайм-аут наступает только через
минуту после запуска; старое догруженное сообщение не становится ответом.
Кнопки ботов: кнопка под последним сообщением бота нажимается по тексту, ответ бота сохраняется; несколько подходящих
или отсутствующая кнопка не нажимаются; кнопка-ссылка отдаёт адрес, кнопка клавиатуры отправляет текст один раз;
нажатие с потерянным ответом не повторяется само. Файл отправляется с подписью, потерянное подтверждение проверяется по
имени файла. Вложение сохраняется в рабочую папку (имя из сообщения или по номеру), чужое имя очищается, сообщение без
файла — понятная ошибка; кнопки и вложения читаются из настоящих объектов Telegram и попадают в событие.
Прокси — на локальном SOCKS5-сервере из теста: ссылки tg://, t.me и socks5:// разбираются, неверные объясняются;
соединение через прокси с логином и паролем, имя сервера передаётся прокси; неверный пароль, прокси без входа,
отказ в соединении и недоступный прокси — понятные ошибки; прокси сохраняется зашифрованным, переживает перезапуск,
пароль не показывается и не теряется при сохранении без него; вход идёт через прокси, молчащий Telegram за прокси даёт
подсказку про прокси; испорченный файл настроек прокси не приводит к подключению напрямую.
Сам сервис — на локальном «молчащем» сервере и закрытом порту: понятный тайм-аут входа, закрытие Pepa во время
входа не ждёт Telegram, неудачный вход не оставляет сессии. Приём сообщений — через настоящий менеджер обновлений
библиотеки без сети (обновления подаются в его обработчик): сообщения принимаются по порядку и не блокируют
библиотеку, состояние сохраняется; непринятое сообщение не продвигает сохранённое состояние; закрытие во время
повторов не ждёт; повреждённый файл состояния не мешает работе. Тесты хоста никогда не обращаются к настоящему Telegram.

Расширения (`Pepa.Host.Tests/PluginApiTests`) — настоящая сборка примера `samples/Pepa.Plugins.Sample` загружается из папки
plugins: блоки появляются в каталоге и выполняются в сценарии (с проверкой результата); повреждённая сборка, пустая
папка и расширение с уже занятым типом блока показаны с причиной, остальная Pepa работает. `PluginLoaderTests` — подмена
раздела палитры, неполные описания блоков, исключения в коде расширения (при подключении, в описании, в проверке
параметров), отказ при запуске от имени администратора, проверка результата в примере по байтам (новый файл, ничего не
дописано, дописана часть строки) и путь только внутри рабочей папки.

Окна Windows (`Pepa.Adapters.Desktop.Tests`) — блоки на имитации Windows и настоящем движке (нажатие без мыши, на
которое программа не ответила, засчитывается только с новым окном программы, иначе — «итог неизвестен»): нажатие без мыши и
мышью, отсутствующее/неоднозначное/недоступное окно или элемент не нажимается, два окна с одинаковым заголовком не
угадываются, ввод проверяется чтением поля, нажатие с неизвестным итогом не повторяется, клавиатура и мышь — только
в найденном окне, сочетания клавиш проверяются при проверке сценария, два процесса не смешивают ввод (ресурс),
закрытие окна идемпотентно. Список элементов окна для конструктора (`Pepa.Host.Tests/DesktopApiTests`) — элементы с
пометкой уникальности имени и ID, окно не найдено, несколько подходящих окон не угадываются, без Windows — понятная
ошибка; выбор элемента в интерфейсе (`ui/src/lib/desktop.test.ts`) — что попадает в поля блока. Запись в окнах
(`DesktopRecordingTests`) — действия с имитации перехвата становятся блоками, и эти блоки выполняются на имитации Windows,
повторяя действия (поле, Enter, нажатие по коду, двойной щелчок, точка в окне, сочетание, правая кнопка, пароль);
неуникальный элемент — пояснение и остановка при выполнении; многострочный текст и повторный ввод — один шаг, а Enter,
который что-то сделал, остаётся; правила клавиш (набор текста / сочетание / не записывается); сокращение заголовка;
API записи (`DesktopApiTests`) и причина недоступности без Windows. Реализация для Windows
(`UiaDesktop`) собирается в CI, но с настоящими программами проверяется у пользователя.

Резервные копии (`Pepa.Engine.Tests/BackupTests`, `Pepa.Host.Tests/BackupApiTests`) — копия одним файлом с данными и
без перезаписи, копия перед обновлением схемы (только один раз), ежедневная копия при запуске и раз в сутки, удаление
старых, копия по кнопке; восстановление из копии: процесс, который после копии успел сделать следующий шаг, после
восстановления сам ничего не повторяет и ждёт решения (только «Продолжить» с предупреждением или «Остановить»), отметка
«база из копии» снимается после первого запуска.

Уведомления (`Pepa.Host.Tests/AttentionNotifierTests`) — о каждой остановке один раз, несколько — одним сообщением,
ждавшие решения до запуска не сообщаются, решение принято — следующая остановка снова сообщается; выключено — только
окно; Telegram не подключён или ошибка отправки — без повторов и без сбоев; после перезапуска — одно сообщение, когда
Telegram подключится; пробное сообщение без Telegram — понятная причина.

`ReviewRegressionTests` — гонки, найденные ревью этапа 2 и воспроизведённые детерминированно (удаление расписания
во время запуска, событие до перезапуска, назначение события во время возврата, сбой во время ожидания и т.д.).

Проверка самих тестов: намеренная поломка восстановления (не помечать прерванные шаги «неизвестно») и обработки
неизвестного итога (считать его обычной ошибкой) роняет соответствующие тесты. Так же проверены тесты этапа 2:
отдача события при равных кандидатах, выдача ресурса приостановленному процессу и продолжение цикла при новом
входе — каждая поломка роняет свой тест.

## Как запустить

```bash
dotnet test Pepa.slnx            # все тесты .NET (~1 минута)
cd ui && npm test                # модульные тесты интерфейса
cd ui && npm run build && dotnet build ../src/Pepa.Server && npm run e2e   # сквозная проверка (нужен Playwright)
```

В CI (`.github/workflows/build.yml`) на каждый push: на Windows — все тесты и сборка приложения (артефакт
`Pepa-win-x64`), на Linux — все тесты и сквозная проверка интерфейса со скриншотами (артефакт `e2e-screenshots`).

## Что проверяется только вручную (на Windows)

- Само окно WPF: запуск, WebView2, выбор папки, «открыть в проводнике», предупреждение при закрытии,
  активация уже открытого окна при повторном запуске. В контейнере разработки окно только компилируется.
